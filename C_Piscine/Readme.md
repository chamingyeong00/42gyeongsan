# C Piscine

42 경산의 입문 과정인 **C Piscine**에서 `Shell00~01`, `C00~C11`, `Rush00~01`, `BSQ` 계열 과제를 수행하며,
단순한 문법 학습이 아니라 **직접 구현과 디버깅을 반복하는 방식으로 C 언어의 동작 원리와 문제 해결 방식**을 익힌 프로젝트입니다.

1달 안에 다양한 과제를 해결해야 했기 때문에, 결과만 맞추는 것보다  
**포인터와 메모리를 어떻게 다뤄야 하는지**,  
**기능을 어떤 단위로 나누어 구현해야 하는지**,  
**제한된 함수만으로도 안정적으로 동작하게 만들 수 있는지**를 계속 고민하며 과제를 진행했습니다.

---

## 프로젝트 소개

C Piscine은 42 커리큘럼의 시작 단계로,  
쉘 환경과 C 언어의 핵심 개념을 짧고 강도 높게 학습하는 과정입니다.

이 과정에서는 이미 준비된 기능을 사용하는 방식보다,  
문자열 처리, 출력, 재귀, 구조체, 2차원 맵 탐색 같은 기본 기능을 직접 구현해야 했습니다.  
그래서 단순히 문법을 아는 것만으로는 해결하기 어렵고,  
**메모리 구조, 포인터 이동, 예외 처리, 함수 분리, 디버깅 과정**까지 함께 이해해야 했습니다.

특히 후반 과제로 갈수록 문제의 정답을 빠르게 작성하는 것보다,  
**어떤 구조로 나누어야 수정과 검증이 쉬운지**가 더 중요한 과제가 많았고,  
이를 통해 구현력과 문제 분해 능력을 함께 훈련할 수 있었습니다.

---

## 구현 목표

이 과정에서 집중한 부분은 다음과 같습니다.

- 제한된 라이브러리 환경에서 기본 기능 직접 구현
- 문자열과 배열을 포인터 기반으로 다루는 방식 이해
- 재귀와 함수 분리를 통한 문제 구조화
- 예외 상황까지 고려한 안정적인 로직 작성
- Rush 과제를 통한 협업형 구현 경험
- BSQ 과제를 통한 2차원 맵 처리 및 알고리즘적 사고 훈련

---

## 주요 수행 내용

### 1. 문자열 및 기초 함수 직접 구현
초반 과제에서는 출력, 문자열 길이 계산, 복사, 비교 같은 기본 기능을 직접 구현했습니다.  
겉보기에는 단순한 함수처럼 보이지만, 실제로는 문자열의 끝을 어디서 판단할지,  
포인터를 어떻게 이동시킬지, 잘못된 접근 없이 원하는 결과를 얻으려면 어떤 조건이 필요한지를 계속 점검해야 했습니다.

이 과정을 통해 라이브러리 함수의 결과만 사용하는 것이 아니라,  
**문자열이 메모리에서 어떤 형태로 다뤄지는지**를 코드 수준에서 이해할 수 있었습니다.

---

### 2. 포인터와 메모리 중심 구현
C Piscine에서 가장 중요했던 부분 중 하나는 포인터였습니다.  
배열과 문자열, 함수 인자 전달, 값 변경 과정이 모두 주소와 연결되어 있기 때문에,  
값 자체보다 **어느 메모리를 가리키고 있는지**를 기준으로 사고해야 했습니다.

특히 포인터를 잘못 다루면 단순 오답이 아니라 프로그램이 비정상적으로 동작할 수 있기 때문에,  
작은 기능이라도 무작정 구현하기보다 **주소 접근과 경계 조건을 먼저 확인하는 습관**을 가지게 되었습니다.

---

### 3. 재귀와 함수 분리
일부 과제에서는 반복문만으로 해결하는 것이 아니라,  
재귀를 사용해 문제를 더 작은 단위로 나누어 해결하는 방식도 연습했습니다.

이 과정은 단순히 문법 하나를 더 배우는 것이 아니라,  
복잡한 문제를 한 번에 처리하려 하지 않고 **작은 기능으로 분리한 뒤 연결하는 방식**을 익히는 데 도움이 되었습니다.  
또한 함수 역할을 명확히 나누지 않으면 디버깅이 급격히 어려워진다는 점도 함께 경험할 수 있었습니다.

---

### 4. Rush 과제를 통한 협업형 구현
`Rush00`, `Rush01`에서는 제한된 시간 안에 팀원과 함께 문제를 분석하고 구현해야 했습니다.  
개별 기능만 잘 작성하는 것으로는 충분하지 않았고,  
함수 이름, 입력과 출력 형식, 역할 분담이 맞지 않으면 전체 프로그램이 쉽게 꼬일 수 있었습니다.

이 과정을 통해  
**혼자 작성하는 코드와 협업을 전제로 작성하는 코드의 차이**,  
그리고 **빠르게 구현하면서도 최소한의 구조를 유지하는 방법**을 실전처럼 경험할 수 있었습니다.

---

### 5. BSQ 과제를 통한 2차원 맵 처리
BSQ 계열 과제에서는 2차원 맵을 읽고, 조건에 맞는 가장 큰 정사각형을 찾는 문제를 구현했습니다.  
이 과제는 단순한 출력 문제와 다르게 입력 검증, 데이터 저장 방식, 탐색 순서, 예외 처리까지 함께 고려해야 했습니다.

특히 중요한 부분은  
- 맵 데이터를 어떤 구조로 저장할지
- 탐색 로직을 어떻게 나눌지
- 잘못된 입력을 어떻게 걸러낼지
- 큰 입력에서도 불필요한 처리를 줄일 수 있을지  
를 함께 고민하는 것이었고, 이를 통해 **구현력과 알고리즘적 사고를 동시에 훈련**할 수 있었습니다.

---

## 프로젝트를 통해 얻은 점

C Piscine을 통해 가장 크게 얻은 것은,  
단순히 C 문법을 익힌 것이 아니라 **왜 코드가 깨지는지 추적하고, 어떤 방식으로 나누어야 안정적으로 구현되는지 판단하는 힘**이었습니다.

과제를 반복하면서

- 포인터와 문자열 처리 오류를 더 빠르게 찾는 습관
- 큰 문제를 작은 기능 단위로 나누는 설계 방식
- 제한된 조건 안에서 우선순위를 정해 구현하는 태도
- 협업 상황에서 코드 구조와 인터페이스를 맞추는 경험
- 단순 정답 제출보다 수정과 확장이 쉬운 코드를 의식하는 습관

을 기를 수 있었습니다.

결과적으로 C Piscine은 입문 과정이었지만,  
저에게는 **C 언어의 저수준 동작, 디버깅 과정, 문제 분해 능력의 기초를 만든 과정**이었습니다.
