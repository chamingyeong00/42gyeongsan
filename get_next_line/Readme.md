# Get_Next_Line

42 커리큘럼의 **Get_Next_Line** 과제를 수행하며 C 언어의 파일 I/O 시스템 콜과 메모리 관리를 학습한 프로젝트입니다.  
단순히 파일을 읽는 것을 넘어, **정적 변수(static variable)**를 활용해 임의의 버퍼 크기에서도 한 줄씩 정확하게 데이터를 추출하는 로직을 설계하는 데 집중했습니다.

---

## 프로젝트 소개

`get_next_line`은 파일 디스크립터(File Descriptor)로부터 호출될 때마다  
개행 문자(`\n`)를 기준으로 **한 줄씩 반환하는 함수**를 구현하는 실습 과제입니다.

함수가 호출될 때마다 다음 작업을 수행해야 합니다.

- 지정된 `BUFFER_SIZE`만큼 파일 읽기
- 읽어온 데이터에서 개행 문자 추출 및 반환
- 반환하고 남은 데이터를 저장하여 다음 호출 시 활용

이 과정에서 함수 호출 간 상태를 유지하기 위해 정적 변수를 사용하고,  
동적 할당된 메모리를 적절히 해제하여 메모리 누수가 발생하지 않도록 관리하는 것이 핵심입니다.

---

## 구현 목표

이 프로젝트에서 집중한 부분은 다음과 같습니다.

- 정적 변수를 활용한 함수 호출 간 데이터 상태 유지
- `BUFFER_SIZE` 크기에 관계없이 동작하는 안정적인 버퍼링 로직 설계
- 힙(Heap) 메모리 할당 및 해제를 통한 엄격한 자원 관리
- 파일 입출력 시스템 콜 `read`의 동작 원리와 파일 끝(EOF) 처리 학습
- 가독성과 효율성을 고려한 문자열 조작 유틸리티 함수 구현

---

## 주요 구현 내용

### 1. 정적 변수(static)를 이용한 잔여 데이터 보관
함수가 종료되어도 읽어온 데이터 중 한 줄을 제외하고 남은 부분을 보관해야  
다음 호출 시 이어서 읽을 수 있기 때문에 정적 변수를 사용했습니다.

- `get_next_line` 내부에 `static char *backup` 선언
- 반환하지 않은 나머지 문자열을 backup에 저장
- 다음 호출 시 이전에 남겨둔 문자열부터 이어서 처리

이를 통해 함수가 끝나도 값이 사라지지 않는 정적 변수의 특성을 이해하고,  
연속적인 데이터 스트림을 끊김 없이 처리하는 방식을 익힐 수 있었습니다.

---

### 2. 효율적인 버퍼 읽기 및 개행 탐색
파일 전체를 한 번에 읽는 대신,  
지정된 버퍼 크기 단위로 필요한 만큼만 읽어 처리하는 방식으로 구현했습니다.

- `while` 루프 내에서 개행 문자(`\n`)가 나올 때까지 `read` 호출
- 읽어온 버퍼를 기존 데이터와 이어 붙이기
- 개행 문자가 발견되면 해당 지점까지 반환할 수 있도록 준비

이를 통해 버퍼 크기가 작거나 커도 안정적으로 동작하는 로직을 설계할 수 있었고,  
시스템 자원을 효율적으로 사용하는 방식도 함께 학습할 수 있었습니다.

---

### 3. 문자열 분리 및 메모리 관리
읽어온 전체 데이터 중에서  
반환할 **한 줄**과 다음 호출을 위해 남겨둘 **잔여 데이터**를 정확히 나누는 과정이 필요합니다.

대표적으로 구현한 내용은 다음과 같습니다.

- 개행 위치까지를 잘라 반환 문자열 생성
- 개행 이후의 문자열은 새 backup으로 갱신
- 기존에 사용한 문자열 메모리는 적절한 시점에 `free`

이를 통해 동적 할당된 문자열을 안전하게 관리하는 방법을 익혔고,  
대용량 파일이나 반복 호출 상황에서도 메모리 누수가 발생하지 않도록 설계하는 습관을 기를 수 있었습니다.

---

## 문제 해결 방식

`get_next_line` 문제를 해결할 때는 아래 순서로 접근했습니다.

1. **매개변수 검증**: 유효한 파일 디스크립터와 버퍼 크기인지 확인
2. **데이터 수집**: 개행이 나타날 때까지 반복적으로 파일 읽기 수행
3. **개행 분석**: 읽어온 문자열에서 첫 번째 개행 문자의 위치 탐색
4. **결과 반환**: 개행까지의 문자열을 잘라 사용자에게 전달
5. **상태 업데이트**: 사용하고 남은 문자열을 정적 변수에 저장하고 기존 메모리 해제

이 과정을 통해 단순한 파일 읽기 함수를 넘어,  
상태를 유지하면서 데이터를 순차적으로 처리하는 로직을 설계할 수 있었습니다.
