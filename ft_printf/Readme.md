# ft_printf

42 커리큘럼의 대표적인 라이브러리 재구현 과제인 **ft_printf**를 C로 구현한 프로젝트입니다.  
표준 `printf`의 핵심 동작을 직접 재현하면서, **가변 인자 처리, 형식 지정자 분기, 자료형별 출력, 반환 길이 관리**를 학습하는 데 집중했습니다.

---

## 프로젝트 소개

`ft_printf`는 표준 `printf`를 그대로 사용하는 대신,  
포맷 문자열을 직접 해석하고 그에 맞는 값을 출력하도록 구현하는 과제입니다.

이 프로젝트에서는 `%c`, `%s`, `%p`, `%d`, `%i`, `%u`, `%x`, `%X`, `%%`를 지원하며,  
단순히 문자열을 출력하는 수준이 아니라 형식 지정자에 따라 적절한 함수로 분기하고,  
출력된 문자 수까지 정확히 반환하도록 구성했습니다.

특히 이 과제에서 중요했던 점은 기능을 한 번에 얽어서 구현하기보다,  
포맷 해석과 실제 출력 로직을 분리해 각 역할을 명확하게 나누는 것이었습니다.  
이렇게 구조를 나누어야 새로운 형식 지정자를 추가하거나 예외 상황을 수정할 때  
전체 흐름을 무너뜨리지 않고 안정적으로 관리할 수 있다고 판단했습니다.

---

## 구현 목표

이 프로젝트에서 집중한 부분은 다음과 같습니다.

- `va_list`를 이용한 가변 인자 처리
- 형식 지정자에 따른 출력 함수 분기
- 문자, 문자열, 정수, 16진수, 포인터 출력 구현
- 출력 길이 누적 및 반환값 관리
- `NULL` 문자열과 포인터 예외 처리
- `write` 기반의 직접 출력 구현

---

## 주요 구현 내용

### 1. 형식 지정자 분기
`ft_printf`는 포맷 문자열을 앞에서부터 순회하다가 `%`를 만나면  
다음 문자를 확인해 형식 지정자에 맞는 출력 함수로 분기하도록 구현했습니다.  
이렇게 만든 이유는 포맷 문자열을 읽는 흐름과 실제 자료형 변환 로직을 분리해야  
코드의 책임이 명확해지고, 디버깅도 훨씬 쉬워지기 때문입니다.  
그 결과 각 지정자별 동작을 독립적으로 관리할 수 있었고,  
전체 출력 흐름도 더 단순하게 유지할 수 있었습니다.

---

### 2. 문자와 문자열 출력
문자와 문자열은 가장 기본적인 기능이지만, 실제 구현에서는 예외 처리가 중요했습니다.  
문자 하나를 출력하는 함수와 문자열을 순회하며 출력하는 함수를 분리해  
가장 작은 출력 단위부터 안정적으로 동작하도록 구성했습니다.  
특히 문자열 포인터가 `NULL`일 때 그대로 접근하면 잘못된 메모리를 참조할 수 있기 때문에,  
`(null)`을 출력하도록 처리했습니다.  
이 덕분에 단순 출력뿐 아니라 예외 상황에서도 표준 `printf`와 유사한 동작을 만들 수 있었습니다.

---

### 3. 정수와 부호 없는 정수 출력
`d`, `i`, `u`는 숫자를 그대로 출력하는 것이 아니라  
숫자를 문자 형태로 변환하는 과정을 직접 구현해야 했습니다.  
이 부분을 직접 만든 이유는 라이브러리 함수에 의존하지 않고도  
정수 출력이 내부적으로 어떤 과정을 거치는지 이해하기 위해서였습니다.  
음수 처리, 0 처리, 자릿수 계산을 직접 다루면서 숫자를 한 자리씩 출력하도록 구성했고,  
그 결과 정수 출력 로직을 자료형별로 분리해 더 명확하게 관리할 수 있었습니다.

---

### 4. 16진수와 포인터 출력
`x`, `X`, `p`는 10진수와 다른 변환 규칙이 필요했기 때문에  
별도의 16진수 출력 로직으로 구현했습니다.  
특히 소문자와 대문자 16진수는 출력 문자 집합만 다르기 때문에,  
같은 변환 구조를 재사용할 수 있도록 구성했습니다.  
포인터 역시 같은 원리를 바탕으로 처리하되 `0x` 접두사를 붙여 출력하도록 했습니다.  
이 방식 덕분에 중복 코드를 줄이면서도, 16진수와 포인터 출력을 일관된 방식으로 관리할 수 있었습니다.

---

### 5. 반환 길이 관리
`printf`는 단순히 출력만 하는 함수가 아니라,  
최종적으로 몇 글자를 출력했는지도 반환해야 합니다.  
그래서 각 출력 함수가 자신이 출력한 문자 수를 반환하고,  
`ft_printf`가 이를 누적해 최종 길이를 반환하도록 구성했습니다.  
이렇게 구현한 이유는 표준 `printf`의 핵심 동작을 최대한 그대로 재현하기 위해서였고,  
동시에 각 함수의 역할을 더 명확하게 나누기 위해서였습니다.  
그 결과 출력 함수들이 단순 보조 함수가 아니라,  
전체 결과를 함께 완성하는 구조로 동작하게 만들 수 있었습니다.

---

## 프로젝트를 통해 얻은 점

`ft_printf`를 구현하면서 단순한 출력 함수처럼 보이는 `printf`가  
실제로는 **가변 인자 처리, 포맷 문자열 해석, 자료형별 변환, 예외 처리, 반환값 관리**가 결합된 구조라는 점을 배울 수 있었습니다.

또한 기능을 문자/문자열, 정수, 16진수/포인터 단위로 나누어 구현하면서  
왜 기능 분리가 필요한지 직접 체감할 수 있었습니다.  
처음부터 모든 로직을 한 함수에 넣기보다 역할별로 나누어 구성했기 때문에  
문제가 생겼을 때 원인을 더 쉽게 추적할 수 있었고, 수정이나 확장도 훨씬 수월했습니다.

결과적으로 이 프로젝트는 단순히 `printf`를 따라 만든 과제가 아니라,  
**입력을 해석하는 방식, 자료형별 변환 구조, 예외 상황 처리, 그리고 함수 단위 설계의 중요성**을 배우는 과정이었습니다.
