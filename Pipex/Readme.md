# Pipex

## 프로젝트 소개
pipex는 UNIX 시스템의 파이프(`|`) 메커니즘을 C 언어로 직접 구현하며, 프로세스 생성, 파이프라인 통신, 리다이렉션 및 명령어 실행의 원리를 심도 있게 학습하는 프로젝트입니다.

이 프로그램은 쉘에서 실행되는 `< infile cmd1 | cmd2 > outfile` 형태의 명령어를 시뮬레이션합니다. 두 개의 명령어를 각각 자식 프로세스에서 실행하고, 첫 번째 명령어의 출력(`stdout`)을 파이프를 통해 두 번째 명령어의 입력(`stdin`)으로 전달하여 최종 결과를 파일에 기록하는 과정을 처리합니다.

---

## 구현 목표

- 자식 프로세스 분기를 통한 멀티프로세싱 환경 이해
- `pipe()`를 이용한 프로세스 간 통신(IPC) 구조 설계
- `dup2()`를 활용한 표준 입출력 파일 디스크립터 리다이렉션
- 환경 변수(`envp`) 내 `PATH` 정보를 파싱하여 동적인 명령어 실행 경로 탐색
- 프로세스 종료 대기 및 자원 누수 방지를 위한 엄격한 메모리/파일 디스크립터 관리

---

## 주요 구현 내용

### 1. 프로세스 병렬 실행 및 파이프 설계
두 명령어가 동시에 실행되면서 실시간으로 데이터를 주고받는 쉘의 파이프라인 기능을 재현하기 위해 단일 프로세스가 아닌 멀티프로세스 구조를 채택했습니다.

대표적으로 구현한 내용은 다음과 같습니다.

- `fork()`를 통해 두 개의 자식 프로세스를 생성하여 독립적인 실행 환경 구축
- `pipe()`로 생성된 파일 디스크립터 쌍을 자식 프로세스들이 공유하도록 설계
- 부모 프로세스에서 `waitpid()`를 호출해 모든 자식 프로세스가 안전하게 종료될 때까지 대기

이를 통해 각 명령어가 독립적인 주소 공간에서 실행되어 안정성이 높아지며, 한 명령어의 결과가 나오는 즉시 다음 명령어로 흐르는 병렬 데이터 스트림을 형성하는 효과를 얻었습니다.

---

### 2. 표준 입출력 리다이렉션 (`dup2`)
`execve`로 실행되는 명령어는 기본적으로 표준 입력(0)에서 읽고 표준 출력(1)으로 쓰기 때문에, 이를 실제 파일이나 파이프 끝단으로 연결해 주는 과정이 필수적입니다.

- `dup2()`를 사용하여 첫 번째 자식의 입력을 `infile`로, 출력을 파이프의 쓰기 끝단(`fd[1]`)으로 교체
- 두 번째 자식의 입력을 파이프의 읽기 끝단(`fd[0]`)으로, 출력을 `outfile`로 교체
- 리다이렉션 완료 후 불필요해진 원본 파일 디스크립터들을 `close()`하여 자원 정리

이러한 구현을 통해 기존 명령어의 소스 코드를 수정하지 않고도 프로그램의 입출력 방향을 자유롭게 제어할 수 있어, 쉘 환경과 동일한 유연한 실행 환경을 제공하는 효과가 있습니다.

---

### 3. 환경 변수 파싱 및 명령어 경로 탐색
사용자가 `ls`나 `grep` 같은 명령어 이름만 입력했을 때, 시스템 내 어디에 실제 실행 파일이 있는지 찾아내야만 프로그램을 실행할 수 있기 때문입니다.

- `envp` 배열에서 `PATH=` 문자열을 탐색한 뒤, 콜론(`:`)을 기준으로 모든 경로를 분할 저장
- 분할된 경로 끝에 `/`를 추가하여 명령어와 결합할 수 있는 형태로 가공
- 결합된 경로를 `access()` 함수로 전수 조사하여 실행 가능한 실제 경로를 반환하는 `check_order` 로직 구현

이를 통해 사용자가 절대 경로를 직접 입력하지 않아도 시스템 환경에 맞춰 명령어를 자동으로 찾아 실행하므로, 범용적이고 사용자 친화적인 도구가 되는 효과를 얻었습니다.

---

### 4. 엄격한 자원 관리 및 예외 처리
프로세스가 예기치 않게 종료되거나 파일 열기에 실패했을 때, 남겨진 파일 디스크립터나 메모리는 시스템 성능 저하 및 좀비 프로세스 문제를 야기할 수 있기 때문입니다.

- 파일 오픈 실패나 실행 오류 발생 시 `perror`와 `exit`를 조합한 `just_error`로 즉각 대응
- `allfree` 함수를 통해 동적 할당된 모든 문자열 배열 메모리를 명시적으로 해제
- `ft_split2` 내부에서 할당 실패 시 이전까지 할당된 메모리를 모두 해제하는 방어적 코드 작성

이러한 처리를 통해 비정상적인 상황에서도 시스템 자원이 누수되지 않고 안전하게 회수되며, 사용자에게 명확한 오류 원인을 전달하여 프로그램의 신뢰성을 확보하는 효과를 보았습니다.

---

## 사용 기술

- **Language**: C
- **Data Structure**: Array of strings (for command arguments and paths)
- **Key Concepts**: IPC (Inter-Process Communication), Process Lifecycle, Redirection, Environment Variables
- **System APIs**:
  - `fork`
  - `pipe`
  - `dup2`
  - `execve`
  - `waitpid`
  - `access`
  - `open`
  - `close`
