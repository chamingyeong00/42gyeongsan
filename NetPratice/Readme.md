# NetPractice

42 커리큘럼의 **NetPractice** 과제를 수행하며 네트워크의 기본 구조와 **IPv4 주소 체계**를 학습한 프로젝트입니다.  
코드를 작성하는 대신 네트워크 토폴로지 문제를 해결하며 **IP 주소 설계, 서브넷 마스크 계산, 라우팅 원리**를 체득하는 데 집중했습니다.

---

## 프로젝트 소개

NetPractice는 주어진 네트워크 구성에서 장치 간 통신이 가능하도록 올바른 값을 설정하는 실습 과제입니다.  
각 레벨을 통과하며 **IP 주소 중복, 서브넷 불일치, 라우팅 경로 오류** 등 실제 네트워크에서 발생할 수 있는 결함을 분석하고 수정하는 과정을 반복합니다.

**왜 통신이 되지 않는지 분석하고, 어떤 값을 수정해야 연결이 가능한지 판단하는 과정**을 통해 네트워크 기본기를 익히는 프로젝트입니다.

---

## 구현 목표

이 프로젝트에서 집중한 부분은 다음과 같습니다.

- IPv4 주소 구조 및 클래스리스(CIDR) 개념 이해
- 서브넷 마스크를 활용한 효율적인 네트워크 대역 분할
- 라우터와 기본 게이트웨이를 통한 패킷 전달 흐름 파악
- 네트워크 통신 장애 발생 시 원인을 분석하고 해결하는 디버깅 능력 배양

---

## 주요 학습 내용

### 1. IP 주소와 서브넷 마스크 설계
각 장치가 속한 네트워크 범위를 정의하기 위해 IP 주소의 구조를 분석했습니다.

- 서브넷 마스크에 따른 네트워크 영역과 호스트 영역 구분
- 사용 가능한 호스트 범위 계산
- 네트워크 주소와 브로드캐스트 주소 구분

이를 통해 단순히 주소를 입력하는 것이 아니라,  
서브넷 마스크 값에 따라 통신 범위가 어떻게 달라지는지 정확히 판단할 수 있었습니다.

---

### 2. 라우팅 및 게이트웨이 설정
서로 다른 네트워크 대역에 있는 장치들이 통신할 수 있도록 데이터 경로를 설계했습니다.

- 라우터 인터페이스별 IP 할당
- 각 장치의 기본 게이트웨이(Default Gateway) 설정
- 다른 네트워크로 나가는 패킷의 전달 경로 확인

이를 통해 라우터가 서로 다른 네트워크를 연결하는 관문이라는 점을 이해하고,  
패킷이 어떤 경로를 따라 이동하는지 구조적으로 파악할 수 있었습니다.

---

### 3. 네트워크 결함 분석 및 문제 해결
통신이 단절된 구성도에서 논리적 오류를 찾아내어 수정하는 과정을 수행했습니다.

- 잘못 설정된 서브넷 마스크 값
- 대역을 벗어난 게이트웨이
- 중복된 IP 주소
- 네트워크 범위에 맞지 않는 인터페이스 설정

이 과정을 통해 네트워크 문제를  
**현상 파악 → 원인 분석 → 수정 → 검증**의 절차로 해결하는 사고방식을 훈련할 수 있었습니다.

---

## 문제 해결 방식

NetPractice 문제를 해결할 때는 보통 아래 순서로 접근했습니다.

1. **토폴로지 분석**: 전체적인 네트워크 연결 형태와 라우터 위치 파악
2. **대역 계산**: 각 인터페이스의 IP와 서브넷 마스크를 바탕으로 네트워크 주소 확인
3. **경로 검증**: 송신지부터 목적지까지 홉(Hop) 단위로 통신 가능 여부 체크
4. **값 수정**: 논리적 충돌이 발생하는 IP나 게이트웨이 설정을 올바른 범위로 변경

이 과정을 반복하면서 네트워크 구조를 단계적으로 해석하고,  
문제의 원인을 논리적으로 좁혀가는 능력을 키울 수 있었습니다.
